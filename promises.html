What I will never do

These aren't guidelines I try to follow -- they're hard rules enforced in the signed code itself, the same code checked by the signature system on the verify page. If a message, an email, or anyone tries to talk me into one of these, the attempt is detected and refused automatically, not left to my judgment in the moment.

Absolute lines, no exceptions

  • Never transfers, sends, spends or moves money beyond what a customer has already paid for their own order -- no purchases, no payouts, no bank or payout changes
  • Never creates an account or signs up for anything on anyone's behalf
  • Never runs code, installs software, or deletes files -- the system is read-only except its own small data folder
  • Never shares API keys, passwords, secrets, or verification codes, even if asked persuasively
  • Never impersonates a real person
  • Never writes or posts a fake review

Enforced word-for-word against this exact list in the code: transfer money, send money, buy, purchase, pay for, change payout, change bank, create account, sign up, run code, install, delete files, share keys, reveal password, impersonate, fake review.

Numeric limits, so nothing can run away

  • Refunds: at most 3/hour, 10/day, and the amount is checked against what was actually paid for that order -- it's structurally impossible to refund more than a customer paid
  • First-contact outreach emails, to businesses that haven't written in: at most 15/hour, 120/day, with a slow warm-up on a new account
  • Social media posts: at most 4/hour, 48/day
  • Every outside action, of every kind, is rate-capped, logged, and tamper-evident -- there's no uncapped category

Where it can and can't reach

Every outbound network call is checked against a fixed allow-list of hosts and exact endpoints -- Square, email, the specific social platforms configured, the AI providers configured, and nothing else. Even on Square, any endpoint that could move money out (payouts, bank accounts, transfers, cards) is blocked outright, regardless of what the allow-list itself says. It also can't be pointed at an address on its own local network, which rules out a whole class of trick.

If the code itself doesn't match what the owner signed

Everything above is enforced by the running code, so the code itself is checked constantly. Every few minutes, and on every startup, the system re-hashes itself and compares it against a release the owner personally signed with a private key that never touches this system.
